# 先认数据，再写代码：零基础起步段

完全零基础的学习者，入门段应该先花大约一小时"看数据"，再写第一行代码。用一份真实的小数据（code-dojo 现成的书店库）讲清这几件事：值分几种（整数、小数、文字、真假、空）；哪些数能拿来算，哪些只是编号；缺失不等于 0；一张表每列只有一种类型，要有一列做主键；数据有单值、一列、一条记录、一张表、嵌套几种形状；CSV 和 JSON 读进程序时都是文字。讲完后，每门语言马上把这些概念落到自己的语法上。这个顺序是**设计上的共识，但没有对照实验支持**。具体来看：教育部两份信息科技课标，以及人教中图版、浙教版教材，都把"数据与编码"放在算法和编程之前。NCRE 二级 Python 2025 年版把 True/False/None、类型判断和转换、比较运算都归进"基本数据类型"一章，排在控制结构之前。MIT 6.100L、py4e、Hyperskill、Helsinki 等英文主流课都在第一单元讲类型，但没有一门设专门的"认识数据"阶段。HtDP、DCIC、Bootstrap:Data Science、Data 8 这些数据优先的课程在头几周就给表，把循环往后放。SQL 课全部从"表 = 行 × 列"讲起，DataCamp 2026 年版更是用整整一章 11 道题只讲概念。给 code-dojo 的推荐是**一条共用的根线，加两层薄绑定**。根线是两条线共用的"认识数据"线，7 个技能，约 20 道看数据作答的题。Python 基础加第 0 组"值和类型"，7 个技能：print、类型转换、input、比较和布尔值从第 1、2 组挪进来，再新增 `py.value-types` 和 `py.type-ops`。SQL 阶段 0 开头加 `sql.select-star` 和 `sql.schema-types` 两个技能。按 track 组织以后，"认识数据"是整张技能图的根：Python 基础和 SQL 的第一组跨线引用它，以后的数据处理、张量、机器学习、手搓 LLM 各自在更深一层回到这批概念。落地需要三件事：一个新题型（看数据作答）；改几条语法识别规则；把 3 道 function 模式的旧题挪到函数之后。

## 课标和等级考试把"数据"排在控制结构前面，英文主流课只在第一单元顺带讲类型

中文权威文件在这件事上的立场最明确。《义务教育信息科技课程标准（2022 年版）》围绕"数据、算法、网络、信息处理、信息安全、人工智能"六条逻辑主线组织内容，要求"循序渐进和螺旋式发展"。**3–4 年级的"数据与编码"模块排在 5–6 年级的"身边的算法""过程与控制"之前**，课标写明"本模块是信息科技课程后续学习的基础"。同一份课标还说，算法模块"不要求每个算法问题都由学生编程实现，阅读理解、修改运行等也都是有意义的体验"（[义务教育信息科技课标 2022](http://www.moe.gov.cn/srcsite/A26/s8001/202204/W020220420582361024968.pdf)）。高中必修 1《数据与计算》的内容要求也是同一个顺序：1.1"描述数据与信息的特征，知道数据编码的基本方式"→ 1.4–1.5 数据处理 → 1.6–1.7 算法与程序实现（[普通高中信息技术课标 2017 年版 2020 年修订](http://www.moe.gov.cn/srcsite/A26/s8001/202006/t20200603_462199.html)）。教材照此执行。人教中图版第 1 章"认识数据与大数据"（含 1.2 数字化与编码）在第 2 章"算法与程序实现"之前，第 2 章的编程部分又按 **2.3.1 数据类型 → 2.3.2 常量、变量及表达式 → 2.3.3 程序语句 → 2.3.4 程序结构**展开（[人教中图版必修 1 目录](http://www.dzkbw.com/books/rjb/xinxijishu/gzbx1/)）。浙教版同样是"数据与信息"（含数据采集与编码）在前，算法和 Python 在后（[浙教版必修 1 目录](http://www.dzkbw.com/books/zjb/xinxijishu/gzbx1/002.htm)）。

面向成人的编程大纲把"数据"落在"数据类型"这一层。NCRE 二级 Python 2025 年版的考试内容依次是：基本语法元素 → **基本数据类型** → 程序的控制结构 → 函数 → 组合数据类型 → 文件和数据格式化 → 程序设计方法 → 计算生态。"基本数据类型"一章同时包括数字类型及运算、**"真假无：True、False、None"**、字符串、**"类型判断和类型间转换"**和**"逻辑运算和比较运算"**。换句话说，学习者写任何 `if` 之前，就该认识真假值和空值，会比较，会转换。列表、集合、字典要等到函数之后；"数据组织的维度：一维数据和二维数据"和 CSV 读写排在第六章（[NCRE 二级 Python 2025 年版](https://jxjy.yznu.edu.cn/_upload/article/files/ba/d9/7ef53e5f49a6a178b0032e40f6b9/5809d0d3-3b83-4bf5-8017-e09cc366138a.pdf)）。嵩天的中国大学 MOOC 现在是第 32 次开课，累计 559 万余人，明确面向零基础学习者和二级考生，顺序几乎相同：第 3 周讲基本数据类型，第 7 周讲"一维/二维数据的格式化与处理"（[课程页](https://www.icourse163.org/course/BIT-268001)；[讲次列表](https://www.bilibili.com/video/BV1JL4y1x7xC/)）。流行教程也一致。廖雪峰的"Python 基础"从"数据类型和变量"（整数、浮点数、字符串、布尔值、空值）开始，第二节就是"字符串和编码"，并点名"None 不能理解为 0"、引号"只是一种表示方式，不是字符串的一部分"（[廖雪峰 数据类型和变量](https://liaoxuefeng.com/books/python/basic/data-types/index.html)）。黑马的基础语法章以**"字面量 → 注释 → 变量 → 数据类型 → 数据类型转换"**开头，布尔类型和比较运算放在 if 那一章的第一节（[黑马 8 天教程](https://www.bilibili.com/video/BV1qW4y1a7fU/)）。没有一份中文材料从 CSV、JSON 这类文件格式起步；JSON 在入门大纲里根本没有出现。

英文主流课有三种排法。第一种是类型先行。MIT 6.100L 第 1 讲把 int、float、bool 和 **NoneType** 并列为四种标量类型，演示 `type()` 和类型转换，然后才讲变量绑定（[6.100L 第 1 讲讲义](https://ocw.mit.edu/courses/6-100l-introduction-to-cs-and-programming-using-python-fall-2022/mit6_100l_f22_lec01.pdf)）。Hyperskill 的知识图里"Basic data types"排第 4，"Variables"排第 5（[Hyperskill topics](https://hyperskill.org/api/topics?track=2)）。py4e、Think Python、ATBS 也都在第一章讲"值和类型"（[py4e 第 2 章](https://www.py4e.com/html3/02-variables)；[Think Python 第 1 章](https://allendowney.github.io/ThinkPython/chap01.html)；[ATBS 第 1 章](https://automatetheboringstuff.com/3e/chapter1.html)）。第二种是输出先行，类型顺带讲。CS50P 第 0 周在"Functions, Variables"里先后碰到 str、int、float；bool 到第 1 周讲条件时才出现；列表到第 2 周才引入，理由是要"理解 for 循环"，先得认识一种"新的变量类型"（[CS50P 第 2 讲](https://cs50.harvard.edu/python/notes/2/)）。第三种是计算器先行，也就是官方 Tutorial，它自己说明不是写给编程新手的（[Python Tutorial](https://docs.python.org/3/tutorial/index.html)）。

这些英文课有几个共同点。**None 是入门大纲里最受冷落的基本值**，只有 MIT 第 1 讲和 Exercism 的 basics 很早就出现它。bool 通常是条件语句的附带内容，只有 Exercism 和 MIT 把它当数据讲：Exercism 的 bools 是独立概念，排在 conditionals 之前（[Exercism config](https://github.com/exercism/python/blob/main/config.json)）。**没有一门课在开头设一个"各种数据放在一起看"的阶段**，集合类型总是在后面单独成单元。freeCodeCamp 把这一点写成了原则："现在先只关注四种类型……其他类型，等你第一次需要时再学"（[fCC 数据类型课](https://github.com/freeCodeCamp/freeCodeCamp/blob/main/curriculum/challenges/english/blocks/lecture-understanding-variables-and-data-types/67fe859a00971c34a23abd43.md)）。py4e 的作者则说明，他把以数字为主的例子换成了以数据为主的练习，并且"按搭建越来越复杂的数据分析方案所需的顺序"安排主题（[py4e 前言](https://github.com/csev/py4e/blob/master/book3/A0-preface.mkd)）。

把这些放在一起看，中文体系里的"从数据开始"其实有两个粒度。课标讲的是**数据这个概念**：特征、编码、组织与呈现。编程大纲讲的是**数据类型**：int、float、str、bool、None 和它们之间的转换。用户提出的"认识不同的数据格式和特点"横跨这两层。类型这一层的先例很充分，NCRE、MIT、Hyperskill、人教中图版都把它放在变量和控制结构之前。概念这一层只有课标和教材在做。"写代码之前先认识 CSV、JSON 这类格式"则没有任何编程大纲这样排，这是 code-dojo 自己的设计选择。可以借用课标的说法，比如"数据的组织与呈现""一维数据、二维数据""类型判断和类型间转换"，但不能说成是照搬现成的做法。

## 数据优先的课程第一周就给一张表，SQL 课无一例外从"行 × 列"讲起

HtDP（2024 年在线版）的第一部分本身就是一个"认识数据"阶段。第 1 章依次讲数字、字符串、图像、布尔值各自的运算，以"1.7 Predicates: Know Thy Data"收尾。设计配方的第 1 步是"从问题分析到数据定义"，函数模板由数据定义直接推出来："数据定义区分几种子类，模板就有几个 cond 分支"（[HtDP 目录](https://htdp.org/2024-11-6/Book/index.html)；[HtDP 第二部分](https://htdp.org/2024-11-6/Book/part_two.html)）。值得注意的是，条件语句并没有被推迟。它在第 4 章随"区间、枚举、分项"这类数据定义一起出现，是数据的形状要求程序分支。

Brown 大学的 DCIC（2025-08-27 版）走得更远。它开篇就批评"大多数入门编程充斥着没有真实意义、不让人感兴趣、也不产生后果的人造数据"，主张"以数据为中心 = 数据科学 + 数据结构（这个加法不能交换）"（[DCIC 概述](https://dcic-world.org/2025-08-27/booklet_intro.html)）。它的顺序是：基本数据（含"类型和契约""名字和字符串的区别"）→ 函数 → 条件和布尔 → **表格数据**（筛选、排序、加计算列、处理缺失项、规范化）→ "从表到列表"（一列就是一个列表）→ 结构化数据和树 → Python 的字典、Pandas、文件 → 最后才讲可变状态和内存模型（[DCIC 目录](https://dcic-world.org/2025-08-27/index.html)）。它定义表时有一句可以直接拿来用的规则："同一列的类型相同，不同的列可以不同"（[DCIC 4.1](https://dcic-world.org/2025-08-27/intro-tabular-data.html)）。

面向中学的 Bootstrap:Data Science 把"数据"放进了第一课。第 1 课讨论"可以对数据集提出哪些问题"，以及"类别数据和数量数据"的区别；第 4–6 课用表画图、取行取格、筛选排序、加计算列；**if-else 到第 10 课才出现**。2020–21 学年约有 8000 名学生用这套课程。前几课全部用同一个"动物收容所"数据集，课程方特意挑了没有缺失值的干净数据，理由引自 Date："缺失值可以有许多种解释，每一种都可能需要不同的处理"（[Bootstrap:DS SIGCSE 2022](https://khoury.northeastern.edu/home/blerner/papers/sigcse2022_ds_curriculum.pdf)）。伯克利 Data 8 的教材更进一步：还没讲"数据类型"，就在第 3 章第 4 节用 `read_table`、`select`、`sort`、`where` 操作一张表；条件语句和迭代推到第 9 章（[Data 8 §3.4](https://inferentialthinking.com/chapters/03/4/introduction-to-tables/)；[Data 8 第 9 章](https://inferentialthinking.com/chapters/09/randomness/index.html)）。这四门课的共同模式是：原子类型（把布尔当作值）→ 用整表操作处理表 → 列变成列表 → 分组聚合 → 显式循环和可变状态放到后面。**没有一门把所有控制结构都推到集合之后**。条件随数据一起出现，被推迟的只是循环和"原地修改"。

SQL 课的开头高度一致。CS50 SQL 第 0 讲先讲"什么是数据库"（一行是一项，一列是一个属性），第一条查询就是 `SELECT * FROM "longlist";`。NULL 紧跟在 WHERE 之后讲；主键、外键到第 1 周和 JOIN 一起讲；数据类型到第 2 周建表时才讲（[CS50 SQL 第 0 讲](https://cs50.harvard.edu/sql/notes/0/)；[第 2 讲](https://cs50.harvard.edu/sql/notes/2/)）。SQLBolt 和 W3Schools 也是"先介绍表，再讲 SELECT"；NULL 分别在第 8 课和第 12 项，类型放在课程最后或参考手册里（[SQLBolt](https://sqlbolt.com/lesson/introduction)；[W3Schools](https://www.w3schools.com/sql/sql_intro.asp)）。PostgreSQL 官方教程在建表之前用一小节讲概念："每一行都有同一组带名字的列，每一列都有确定的数据类型……SQL 不保证表中行的顺序"（[PostgreSQL 2.2](https://www.postgresql.org/docs/current/tutorial-concepts.html)）。

最接近"认识数据和表"阶段的，是 DataCamp 2026 年 10 月更新的《Introduction to SQL》。它的第 1 章有 3 段短视频和 8 道小题，**一行 SQL 都不用写**：用选择题判断数据库的结构，给 books 表挑唯一标识，判断哪种命名合规，"运行给好的 `SELECT * FROM books;`，现在还不用写任何东西"，回答去哪里找每列的类型，判断 `price 63.75` 该用什么类型。第 2 章才开始填 `SELECT ___ FROM ___;`。它给的理由是"写任何 SQL 查询之前，先理解底层数据很重要"（[DataCamp 第 1 章](https://campus.datacamp.com/courses/introduction-to-sql/relational-databases?ex=4)；[练习 7](https://campus.datacamp.com/courses/introduction-to-sql/relational-databases?ex=7)；[练习 11](https://campus.datacamp.com/courses/introduction-to-sql/relational-databases?ex=11)）。这门课评分 4.8（68,252 条评价），历史报名 1,626,692 人（[课程页](https://www.datacamp.com/courses/introduction-to-sql)）。Select Star SQL 站在另一端：它认为"编程最好在做中学"，学 SQL 就是建立一个能预测查询输出的心智模型（[Select Star 前言](https://selectstarsql.com/frontmatter.html)）。NCRE 二级 MySQL 2025 年版同样以"基本概念与方法"（数据模型、关系模型）开篇，"表结构、表数据的基本概念"先于一切表操作，完整性约束排在查询之后（[NCRE 二级 MySQL 2025](https://jxjy.yznu.edu.cn/_upload/article/files/ba/d9/7ef53e5f49a6a178b0032e40f6b9/93fbb5d7-5fad-4868-a11d-a0b253751745.pdf)）。

| 课程 | 第一条查询之前讲什么 | 类型何时讲 | 主键何时讲 | NULL 何时讲 |
|---|---|---|---|---|
| CS50 SQL | 数据库、表、行、列；为什么不用电子表格 | 第 2 周建表时 | 第 1 周，随 JOIN | 第 0 讲，WHERE 之后 |

还有一个对 code-dojo 有利的巧合：和它定位最接近的几门课都用图书数据，比如 CS50 的国际布克奖书单和 DataCamp 的图书馆（[CS50 SQL 第 0 讲](https://cs50.harvard.edu/sql/notes/0/)；[DataCamp 第 1 章](https://campus.datacamp.com/courses/introduction-to-sql/relational-databases?ex=1)）。书店库正好合群。

这些排法的证据分量必须说清楚：**它们是设计共识，不是实验结论**。我没有找到任何一项对照研究，比较"数据先行"和"控制结构先行"对成人自学者的效果。Bootstrap:DS 的评估自称"非常初步"：技能测验只收到 23 份学生答卷，作者说样本"小到任何细致解读都没有意义"；感受问卷 94 人里 96.9% 同意"我学到了一些编程"，作者也承认这"够不上结论"（[Bootstrap:DS SIGCSE 2022](https://khoury.northeastern.edu/home/blerner/papers/sigcse2022_ds_curriculum.pdf)）。DCIC 没有发表学习效果数据。常被引用的 Rainfall 研究覆盖 4 所学校的 5 门函数式 CS1，但比较的对象是以往发表的命令式课程结果，不是匹配的对照组（[Fisler ICER 2014](https://typeset.io/pdf/the-recurring-rainfall-problem-4w0k80zfy6.pdf)）。也没有研究检验过"先学表"能不能帮助后面学 SQL。

比较扎实的是另一类证据：新手关于数据和布尔值的误解确实存在，而且可以一条条命名。progmiscon 的 Python 误解库收录了 ComparisonWithBoolLiteral（以为必须和 True/False 比较）、MapToBooleanWithIf（以为要得到布尔值必须写 if）等条目（[progmiscon Python](https://progmiscon.org/misconceptions/Python/)）。研究发现变量和布尔逻辑对新手很难（[Grover & Basu 2017](https://www.doi.org/10.1145/3017680.3017723)）。SQL 误解的四个来源之一就是"其他课程带来的旧知识"（[Miedema 等 2021](https://icer2021.acm.org/details/icer-2021-papers/22/Identifying-SQL-Misconceptions-of-Novices-Findings-from-a-Think-Aloud-Study)）。至于最常见的坑，`"5"` 和 `5` 分不清、不知道 `input()` 返回字符串，只有课程材料记录过（[BU CS111 常见错误](https://www.cs.bu.edu/courses/cs111/problem_sets/errors.shtml)），没有专门的研究。学习科学还有两条一般结论：低先备知识者从高指导中获益，约 d = 0.5（[Tetzlaff 等 2025](https://doi.org/10.1016/j.learninstruc.2025.102142)）；只读不写会让人高估自己（[Gold 等 2026](https://escholarship.org/uc/item/6vq9j198)）。综合起来，合理的结论是：起步段可以先讲数据，但不写代码的部分必须短，并且尽快换成要动手、能判对错的练习。

## 能直接借鉴的练习分三类：给值和列分类、同样的字符不同的类型、看表作答

上面这些来源留下了一批现成的题型，基本可以原样搬进 code-dojo。第一类是**分类题**。MIT 第 1 讲的"YOU TRY IT"让学生在控制台里查 1234、8.99、9.0、True、False 的类型（[6.100L 第 1 讲](https://ocw.mit.edu/courses/6-100l-introduction-to-cs-and-programming-using-python-fall-2022/mit6_100l_f22_lec01.pdf)）。Bootstrap 的评估题让学生把电影表的每一列归为"类别、数量、都不是"，再给每列选一个程序里的类型。试点里最明显的混淆，恰恰出在"看着是数字其实是类别"的值上，例如演播室编号（[Bootstrap:DS](https://khoury.northeastern.edu/home/blerner/papers/sigcse2022_ds_curriculum.pdf)）。书店库里的 book_id、手机号、ISBN 就是这一类。

第二类是**同样的字符、不同的类型**。Helsinki 第 1.1 节对比 `print(2 + 2 * 10)` 和 `print("2 + 2 * 10")`（[Helsinki 1.1](https://programming-26.mooc.fi/part-1/1-getting-started)）。第 1.3 节对比整数相加和字符串相加，展示 TypeError 和修法，并解释"类型重要，是因为同一个运算对不同类型的值作用不同"（[Helsinki 1.3](https://programming-26.mooc.fi/part-1/3-more-about-variables)）。Think Python 用 `'126'` 说明"看着像数，其实是字符串"，`'126' / 3` 会报 TypeError（[Think Python 第 1 章](https://allendowney.github.io/ThinkPython/chap01.html)）。py4e 第 2 章练习 4 要求写出 `width // 2`、`width / 2.0`、`height / 3` 的值**和**类型（[py4e 第 2 章](https://www.py4e.com/html3/02-variables)）。Helsinki 第 2.1 节把"表达式 → 值 → 类型"列成一张表，可以直接拿来当课里的示例格式（[Helsinki 2.1](https://programming-26.mooc.fi/part-2/1-programming-terminology)）。

第三类是**看数据作答**。Bootstrap 的"Table Interpretation"问一张表能回答哪些问题、不能回答哪些问题。它的数据质量题给出 `"yes"/"false"/"nope"/"no"` 和 `5.5 / "4ft 10in" / "61 inches" / 72` 这样的列，问"能不能直接用"，再让学生修好一列。Gu 等人的研究把同一份数据的两种组织方式并排给学生对比，大一新手能说出取数和更新上的差别，但看不出性能和隐私上的差别（[Gu 等 ICER 2020](https://cs.brown.edu/~sk/Publications/Papers/Published/ghlrfk-design-alt-data-org/)）。DataCamp 的练习 5、7、11 则是挑唯一标识、运行给好的 `SELECT *`、给 `63.75` 选类型。

## 推荐一条两线共用的"认识数据"根线，再给两门语言各加一层薄绑定

可选的做法有三种：只在 Python 0A 之前加一段，只在 SQL 阶段 0 之前加一段，或者做成两条线共用的起步段。推荐第三种，但要拆成两层。共用的那一层只讲**跟语言无关的概念**：值分几种，数量和标签，缺失，每列一种类型和主键，数据的形状，CSV 和 JSON。它是一条独立的小线，7 个技能，全部用"看数据作答"的题练。每门语言再各加一层薄的**绑定组**，把概念落到自己的语法和行为上：Python 基础第 0 组讲字面量、`type()`、类型决定运算、转换、`input()`、布尔值；SQL 阶段 0 开头讲 `SELECT *` 和表结构。

这样拆有四个理由。第一，概念层与语言无关，而且以后每条线都要用。用户已经决定把知识点按 track 整理，并计划加数据处理、张量、模型训练、手搓 LLM。写一次放在根上，比在 Python 和 SQL 里各写一遍、以后在 pandas 里再写一遍省事；学习者也可以不学 Python、直接从 SQL 起步。

第二，两门语言的**具体行为恰恰不同**，不能放进共用层。Python 里 `None == None` 是 True，PostgreSQL 里 `x = NULL` 的结果是 null 而不是 true（[PostgreSQL 比较运算](https://www.postgresql.org/docs/current/functions-comparison.html)）。Python 的 `7 / 2` 是 3.5，PostgreSQL 的整数相除会截断（[PostgreSQL 数学函数](https://www.postgresql.org/docs/current/functions-math.html)）。"其他课程带来的旧知识"本来就是 SQL 误解的来源之一（[Miedema 等 2021](https://icer2021.acm.org/details/icer-2021-papers/22/Identifying-SQL-Misconceptions-of-Novices-Findings-from-a-Think-Aloud-Study)）。所以共用层只说"缺失"，不说 None 也不说 NULL；None 和 NULL 各自在自己的线里教。

第三，不写代码的部分必须短，而且要让学习者自己写出答案。只读不写会让人高估自己（[Gold 等 2026](https://escholarship.org/uc/item/6vq9j198)），DataCamp 的概念章也只有 3 段短视频加 8 道小题。所以根线定在 7 个技能、每个 2–3 题，约一小时（这是估算），答案尽量要求打字而不是只点选项，做完马上进入要写代码的绑定组。

第四，用同一份数据。Bootstrap 前几课只用一个数据集，code-dojo 的书店库则已经故意放好了根线需要的边界：两本同名不同版的书、两位同名用户、库存为 0 的书、空的出版社和城市。"书名能不能当主键""空和 0 一样吗"这些题，用的就是学习者之后会去查询的那几行。

反对意见里最有力的是 freeCodeCamp 和 CS50P 的"用到时再学"：脱离代码先讲抽象概念，零基础的人没有地方挂靠。回应有三点。根线短，而且每个概念在一小时之内就会在绑定组里被代码用到。Python 和 SQL 第一组的题会把根线技能写进跨线前置，"认识了却不用"的情况在结构上不会发生。根线的题要求打字作答，错误答案直接映射到具名误解，不是让人被动读。

另一种做法是像 Data 8 和 DCIC 那样，在 Python 里一开始就用表（字典的列表）。这对 Python 基础不合适，原因有三：纯 Python 处理表需要推导式或循环；DCIC 依赖的是 Pyret 内置的表操作；code-dojo 的检查脚本会把列表、字典字面量算作第 5、7 组的技能。更合适的位置是将来数据处理线的第一组"表格数据（纯 Python）"。在那里显式对照 SQL：选列对应 `SELECT`，筛行对应 `WHERE`，排序对应 `ORDER BY`，按类别计数对应 `GROUP BY`。DCIC 和 Data 8 的整表操作正是这样一一对应 SQL 子句的（[DCIC 4.1](https://dcic-world.org/2025-08-27/intro-tabular-data.html)）。

### 在按 track 组织的结构里：它是根，各条线在更深一层回访

按目前的打算，每条线一个 `track.yaml`，技能可以跨线写前置；现在的 python 拆成"Python 基础"和"算法与数据结构"；进阶另加数学、数据处理、张量与 PyTorch、机器学习手写、训练、手搓 LLM。在这个结构里，"认识数据"应该是**一条独立的根线**，线 id 用 `data`，只有一个阶段，没有任何前置，首页默认排第一。

Python 基础第 0 组和 SQL 阶段 0 的第一批技能跨线引用它。算法与数据结构只通过 Python 基础间接依赖它。跨线前置的门槛建议用"已学"而不是"已掌握"：学习者一口气做完根线就能进入写代码的部分，根线技能的掌握在后面那些用到它们的代码题里自然积累。这也是《义务教育信息科技课标》"数据"主线的结构：同一批概念在不同学段反复出现，每次更深一层，课标称之为"螺旋式发展"。

下表是根线概念在各条线里的回访点。这是设计推断，不是引用：

| 根线里的概念 | Python 基础 / SQL | 数据处理 | 张量与 PyTorch | 机器学习、手搓 LLM |
|---|---|---|---|---|
| 值的种类 | int、float、str、bool、None；integer、numeric、text、date | 每列的 dtype、类型转换 | 张量的 dtype | token id 是整数，embedding 是小数 |
| 数量还是标签 | ISBN、手机号存成文字 | 类别型的列 | — | 类别特征要 one-hot 或 embedding，不能直接比大小 |
| 缺失值 | None；NULL 和三值逻辑 | NaN，填补还是丢弃 | NaN 在计算里传播 | 缺失特征处理；padding 和 mask |
| 每列一种类型、主键 | 表结构、主键 | 索引；一列一个 dtype | 一个张量只有一个 dtype | — |
| 数据的形状 | 列表、字典、二维列表；表和连接 | Series、DataFrame、分组 | shape、维数、广播 | 样本 × 特征；batch × 序列 × 维度 |
| CSV 和 JSON | 读文件，csv / json 模块 | 读 CSV、读 JSON | — | 文本语料 → 分词 |

Python 第 4 组的 `ord` / `chr`（字符编码）留在原位，因为它需要下标和循环才能练。课标反复强调的"编码"会在手搓 LLM 线以分词的形式回来。

## 技能清单：根线 7 个、Python 第 0 组 7 个、SQL 开头 2 个

### 认识数据根线：7 个技能，约 20 道看数据作答题

根线的题用一个新题型 `format: inspect`（看数据作答）。题面是一个数据块加一个问题，数据块可以是表格、CSV 文本、JSON 文本、表结构或一串值。答案有两种形式：单选，或者打一个短答案（数字、列名、类型名）。错误选项或错误答案映射到具名误解，做法和前一份报告给预测题设计的"错误输出 → 误解编号"一致。课里的示例换成一个可以编辑的数据块，有"表格 / CSV / JSON"三种视图：改一个 CSV 单元格，表格视图跟着变。数据全部取自书店库。前三个技能只给干净的子集，这是 Bootstrap 的做法；第四个技能才故意把缺失值放进来。

| 顺序 | 技能 id | 名称 | 前置 | 练习（每个 2–3 题） | 针对的误解 |
|---|---|---|---|---|---|
| 1 | `data.table-intro` | 一张表：行是一条记录，列是一种属性 | — | 数 books 子表有几行几列；用眼睛找答案（库存为 0 的有几本）；判断哪些问题这张表能回答（"这本书卖了几本"不能，要看订单） | — |

| 3 | `data.quantity-vs-label` | 数量还是标签：哪些数能拿来算 | 2 | 哪几列求平均有意义（价格、页数能；book_id、手机号不能）；ISBN 该存成数还是文字 | DM04 由数字组成就能算 |

顺序的依据是：先给一张表，因为 Data 8 和 Bootstrap 第 1 课都是这样开头的；再讲值和"能不能算"；缺失值放在看过干净数据之后；类型和主键对应 DataCamp 的第 1 章；形状对应 NCRE 的"一维数据、二维数据"和课标的"数据的组织与呈现"；文本格式放在最后，因为它要用到前面所有概念。

把 `py.print` 留作入口，是因为预测题离不开它；Helsinki 1.1 和 freeCodeCamp 最新的第一课（先只敲一个 `'Hello'` 字面量，再包上 print）也是先让人看"值"本身（[fCC 第一个程序](https://github.com/freeCodeCamp/freeCodeCamp/tree/main/curriculum/challenges/english/blocks/workshop-first-python-program)）。`py.value-types` 放在 `py.var-arith` 之前，依据是 MIT、Hyperskill、人教中图版"类型先于变量"的排法，以及黑马的"字面量"开篇。`py.type-ops` 从 `py.type-convert` 里拆出来，对应 Helsinki 把"区分类型"（1.3）和"转换类型"（1.4）分成两节（[Helsinki 1.4](https://programming-26.mooc.fi/part-1/4-arithmetic-operations)），也符合"每题最多引入 1 个新技能"。`py.compare-bool` 提到 if 之前，依据是 NCRE 把比较运算和"真假无"放进基本数据类型、Exercism 的 bools 先于 conditionals，以及 progmiscon 的 MapToBooleanWithIf。

第 0 组共约 20 题：保留的旧题 10 道（001、101、002、102、103、104、110、111、008、009），新题约 10 道。新增 Python 误解：PM51 PrintRevealsType（`print(7)` 和 `print("7")` 显示一样，所以是同一种值）、PM52 BoolNeedsIf、PM53 IntParsesDecimal（`int("3.5")` 得到 3）、PM54 TypeErrorVsValueError。原第 1 组剩下 `py.func-return`、`py.floordiv-mod`、`py.fstring`，改名"函数、整除和格式化"；第 2 组从 `py.if-else` 开始。

### 落地要改的六处

**题型。** 新增 `format: inspect`，支持单选和短答案两种作答，错误答案映射到误解编号，数据块支持表格、CSV、JSON、表结构四种显示。课的 example 步骤要允许放数据块。根线里的看数据作答题计入掌握。

**识别表。** `check_curve.py` 里，`type` 调用从 `py.class-basic` 改指 `py.value-types`；`none-const` 从 `py.none` 改指 `py.value-types`；`bool-const` 从 `py.compare-bool` 改指 `py.value-types`。`compare-is` 仍归 `py.none`。SQL 规则里，`SELECT *` 单独映射到 `sql.select-star`。

**技能图。** `STAGE_ORDER` 加上 `data`；加载技能时读入全部线，并支持跨线前置；课 id 和题 id 的正则要允许 `data-` 前缀。

**课文件。** 新建 `py-0a-l00-values`，把 print、type-convert、stdio-input 的讲解从 `py-0a-l01-basics` 搬过来，把 compare-bool 的讲解从 `py-0a-l02-conditions` 搬过来，因为每个技能只能在一个文件里讲。新建 `sql-0-l00-tables`。根线新建两个课文件 `data-0-l01-values`（技能 1–4）和 `data-0-l02-shapes`（技能 5–7）。课文里本来就禁止写"上一节""下一组"之类的位置引用，所以搬动不用改正文。

**题目。** 新写约 10 道 Python 题、4 道 SQL 题、20 道看数据作答题；3 道 function 模式的旧题挪位。

**误解目录。** 在 `docs/teaching-design.md` 里加上 DM01–DM08 和 PM51–PM54。

需要用户拍板的有三点。第一，看数据作答题算不算"计入题"，我的默认是只在根线里算。第二，跨线前置的门槛是"已学"还是"已掌握"，我的默认是"已学"。第三，根线 7 个技能是否默认全部排在写代码之前，我的默认是全部排在前面，但 Python 第 0 组只硬性要求技能 1–2，SQL 开头只硬性要求技能 1、2、4、5。

## 结论

用户"应该从认识不同的数据格式和特点开始"的直觉，和中文课标的思路一致，和英文主流课的做法不一致。"数据类型"大家都在第一周讲；"数据格式和特点"则没有一门编程大纲放在开头。code-dojo 恰好落在这个空档上，所以应该把根线当成一次有指标的尝试，而不是已被证明的做法。好在平台已经具备测量它的手段：预测题和看数据作答题的错误答案都映射到具名误解。做过几周后看两个信号。如果 DM01、DM03、DM04 在 Python 第 0 组和 SQL 阶段 0 第一次出现时就几乎没人犯，说明根线可以压缩；如果"空就是 0"一直延续到 SQL 的 NULL 题和聚合题，就该加厚 `data.missing`。

更大的收益在下游。NCRE 的"一维数据、二维数据"往前推一步就是张量的维数，"数量还是标签"到机器学习里就是 one-hot，"缺失"会变成 NaN 和 mask，第 4 组的字符编码会变成分词。所以写根线的题时，就应该照着这些后续用途来出题。例如 `data.shapes` 问"定位一个值要几个下标"，这正是 ndim 的定义；`data.value-kinds` 区分"整数编号"和"小数度量"，这正是 token id 和 embedding 的区别。现在多花这一点心思不增加成本，等张量线和手搓 LLM 线上线时，就能直接跨线引用，不用重写入门。
