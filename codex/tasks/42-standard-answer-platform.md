# 42-standard-answer-platform：做对之后能看的参考答案

## 背景

用户 2026-11-23："每题我做完正确以后 最好有一个比较标准的参考答案可以选择性的查看这样，因为比如说我可能虽然写对了但是写法不够简洁或者不够optimal我可以看一下标准解法然后回去对齐优化什么的"。

内容量很大（约 1300 道代码题），用户要求"全给codex去做吧 要确保代码优雅简洁，以教学为核心，禁止防御型写作"，说明选"简短说明"。

这个任务只做**平台和写法规范**，再为 5 道示范题写出参考答案（见第 4 节）。其余题目由后续的内容任务按线分批写。

现状：
- 每道题已有 `solution.py` / `solution.sql`，用来验题。
- 做题页有"看完整题解 · 明天重写"（`api.solution`）：看了就排进明天的重写，复习时直接结束本轮。
- 这个流程保持不变。新的"参考答案"只在**这道题已经通过之后**才给看，看了不影响掌握度。

## 要做的事

### 1. 格式（`docs/problem-format.md` 升一个小版本，写清改了什么）

每道代码题（`format` 不是 `predict` / `inspect`）可以有：

- `standard.py` 或 `standard.sql`：标准写法。
  - 必须通过这道题全部的 examples 和 hidden 测试，判法和 `solution.*` 相同，包括 checker、constraints、SQL 的 mode。
  - 只能用 `requires ∪ {introduces}` 里的技能，用 `check_curve.py` 对 `solution` 的那套 AST / SQL 技能识别来检查。
- `standard.md`：简短说明，固定小节：
  - `## 思路`：2–4 句。
  - `## 复杂度`：算法题必写时间和空间；SQL 和数据科学题写不写看有没有意义。
  - `## 写法要点`：和常见写法比，好在哪里，1–3 条。
  - 可选 `## 进阶写法`：一个 ```python 或 ```sql 代码块，可以超纲（比如 `collections.Counter`、生成器、窗口函数的简写），配一两句说明。这段代码也要通过全部测试，但不做技能检查。

没有 `standard.*` 的题，参考答案标签退回显示 `solution.*`，不带说明。

### 2. 写法规范（写进 `docs/teaching-design.md` 新的一节「参考答案的写法」，后续内容任务照这一节写）

- **以教学为核心**：代码就是讲解的一部分。变量名用题目里的业务词，比如 `price`、`seen`、`left`、`window_sum`，不用 `x1`、`tmp`。一个函数做一件事，读起来从上到下就是思路的顺序。
- **优雅简洁**：没有多余的中间变量、重复计算和死分支。能直接 `return` 的就不先赋值再返回。Python 风格遵守 PEP 8，在已学技能范围内尽量地道，比如 `enumerate`、`zip`、推导式。
- **禁止防御型写法**：
  - 不校验题目保证合法的输入；
  - 不包 `try/except`，除非题目本身就要求处理异常；
  - 不写"以防万一"的分支，不给空输入写特判，除非约束允许出现空输入；
  - 不 `assert` 参数类型。
- **注释**：只在讲关键一步时写，最多 2–3 处，可以沿用课里的子目标编号 ①②③。不写复述代码的注释。
- **SQL**：
  - 关键字大写，每个子句单独一行；
  - CTE 名字说清这一步产出什么；
  - 不写不必要的子查询和 `DISTINCT`；
  - 连接条件写全；
  - 窗口函数优先于自连接，前提是已经学过。
- **算法题**：
  - 写出最优或面试期望的复杂度；
  - 如果更朴素的写法也能过，在「写法要点」里点明差别。

### 3. 校验与工具

- 新脚本 `scripts/curriculum/verify_standard.py`：
  - 支持 `--only <题号前缀>` 和 `--track`。
  - 对每道有 `standard.*` 的题：跑测试；做技能检查；`standard.md` 的小节齐全、`## 进阶写法` 的代码块能过测试。
  - 输出逐题结果和汇总，比如"有参考答案 N 道，通过 N，失败 0"。
- `scripts/verify_bank.py` 的全库验证里带上参考答案。`check_curve.py` 把 `standard.*` 纳入技能检查。
- 内容任务会并行地按线跑这个脚本，所以 `--only` 要快，不加载无关的线。

### 4. 示范答案（给后续内容任务当样板）

为这 5 道题写 `standard.*` 和 `standard.md`，按第 2 节的规范，都要通过 `verify_standard.py`：
- `py-0a-409-write-cheaper-price`
- `py-0a-104-write-flower-bed`
- 算法阶段 1 的一道哈希表题（如 Two Sum）
- 一道滑动窗口题
- `sql-0-001-book-titles` 或一道带 CTE 和窗口函数的 SQL 题

### 5. 后端接口

`GET /api/problems/{id}/standard`：
- 只有这道题已经有一次正式通过（solved 或 assisted），才返回 `{code, language, notes_md, advanced_md, has_notes}`；
- 没通过返回 403，带中文说明；
- 附加题和预测、看数据题返回 404。

不记求助，不影响掌握。

### 6. 前端

- 做题页左侧标签条：这道题已经通过时，出现"参考答案"标签；刚刚提交通过时也立刻出现，不用刷新。
- 标签内容依次是：
  1. 渲染好的思路 / 复杂度 / 写法要点；
  2. 标准写法（只读 Monaco，带语法高亮）；
  3. "和我的代码对比"按钮：用 Monaco 的 DiffEditor 左右对照，左边是编辑框当前的代码，右边是标准写法，只读，深浅主题都正常；
  4. `## 进阶写法`（如果有）放在最后，Markdown 渲染。
- 命令面板加"打开参考答案"。
- 风格遵守 `.impeccable.md`。
- 没通过时这个标签不出现，原来的"看完整题解 · 明天重写"保持不变。

## 不做

- 不批量写参考答案，只写第 4 节的 5 道示范，其余交给后续内容任务。
- 不改 `solution.*`。
- 不改 `desktop/`、`bootstrap/`。
