## 文档要回答的问题
1. **目标和不做什么**：记忆用来解决什么问题，明确不记什么（敏感信息、一次性手误、能从数据库算出来的数字）。
2. **数据模型**：表结构、字段、分类，和事件日志怎么接。**跨机器合并的语义**必须基于读到的 `events.py` / `sync.py` 实际行为来写，比如两台机器同时改同一条时怎么处理、删除怎么同步，不要凭想象。
3. **读**：提示词里放什么、按什么挑相关条目、字数上限多少；由数据生成的进度摘要从哪些表来。估算每次调用多出多少输入字数，对订阅额度的影响写一句。
4. **写**：`memory` 字段的 schema（兼顾 Claude 的 `--json-schema` 和 Codex 的严格 schema）；后端校验规则；提示词里怎么约束"什么值得记"；学生说"记住……"时怎么处理。
5. **整理**：什么时候触发、谁来跑、怎么避免把用户手写的条目改坏。
6. **界面**：助教回复下的"已记下"和撤销；记忆页面放在哪、能做什么；设置里的开关和清空。要符合 `.impeccable.md`。
7. **三个待定问题**：每个给出推荐、理由和排除的选项。
8. **分期**：第一期（最小可用、能尽快用上）做什么，后面几期做什么。每期列出要改的文件、要加的测试、大致工作量（按以往一个 codex 任务 15–30 分钟估）。
9. **风险和开放问题**：需要用户决定的事单独列一节，每条给推荐的默认值。

## 写法
- 中文，写"会是什么样"，不写成讨论记录。能用表格的地方用表格。控制在约 300 行以内。
- 涉及现有代码的地方写清文件和函数名，方便后面派任务。
- 不要虚构代码里没有的接口；拿不准的标"待确认"。
