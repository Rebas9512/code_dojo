# 28 · 令牌加密打包进安装包（每台电脑只输一次密码）+ 收尾打磨

## 背景

用户 2026-11-22 说：
- "能不能把令牌也打包到里面"
- "好的那就走加密路线好了，我把两个令牌都放到env文件里了"

主控定的方案：
- **令牌用用户的密码加密后放进安装包**。新电脑第一次打开时，只输这个密码，不用再去 GitHub 建令牌、复制粘贴。
- 安装包被别人拿到，没有密码也解不开。
- **令牌明文绝不能进仓库、日志、报告、截图**；你这次也**不读、不打印**用户的真实令牌。

现状：
- 26 号任务做的桌面应用，第一次打开时在 Tk 控制窗口里让用户粘贴两个 fine-grained 令牌：
  - 代码仓库 `Rebas9512/code_dojo`，Contents 只读；
  - 同步仓库 `Rebas9512/code_dojo_sync`，Contents 读写。
- 令牌存在系统钥匙串，或者数据目录的 `github-tokens.json` 里。
- 安装包由 `.github/workflows/release-app.yml` 在 `app-v*` 标签时构建。

用户把两个令牌放在工作目录根上的 `.env` 里，路径相对项目根是 `../../.env`。变量名分别是 `code_dojo` 和 `code_dojo_sync`。这个文件在 git 仓库之外。

**并行**：这次只有你一个任务在跑。

## 要做的事

### A. 令牌加密打包

**1. 加密脚本** `scripts/desktop/seal_tokens.py`（用户自己在终端运行）：
- 参数：
  - `--env <路径>`：默认 `../../.env`。
  - `--keys code_dojo,code_dojo_sync`：变量名可改。
  - `--repo Rebas9512/code_dojo`：存 Actions 密钥的仓库。
  - `--out <文件>`：可选，另外存一份加密结果到本地。
  - `--no-upload`：只生成，不上传。
- 读 `.env`，**不打印任何令牌内容**，只打印"已读取 2 个令牌"。
- **先校验两个令牌能用**，都只调只读的 GitHub API：
  - 代码令牌能列出 `code_dojo` 的 Releases；
  - 同步令牌能读 `code_dojo_sync` 的 README。
  - 失败就给出中文原因，比如"代码仓库令牌缺少 Contents 读权限"，然后退出。
- 用 `getpass` 让用户输两遍密码。少于 10 个字符就提示太短并要求重输。
- **加密**：
  - 用 `cryptography` 的 AES-256-GCM；
  - 密钥用 scrypt 派生（`hashlib.scrypt`，n = 2^17、r = 8、p = 1，随机 16 字节盐）；
  - 关联数据里放版本号和两个仓库名。
- **输出 JSON**，包含：版本号、kdf 参数、salt、nonce、密文（base64）、仓库名、生成时间。不含明文。
- **上传**：用 `gh secret set CODE_DOJO_SEALED_TOKENS --repo <repo>`，内容走 stdin，不经过命令行参数和临时文件。用的是本机已经登录的 `gh`。
- 最后提示用户：
  - 可以删掉或者妥善保管 `.env`；
  - 下一步是打新的 `app-v*` 标签，重新构建安装包。

**2. 构建时放进安装包**：`release-app.yml` 在三个系统的构建步骤里：
- 如果 `secrets.CODE_DOJO_SEALED_TOKENS` 存在，就写成包里的 `sealed-tokens.json`；
- 不存在就跳过，回到手动粘贴令牌的老流程；
- 日志里不能回显它的内容。

**3. 启动器**（`bootstrap/`）取令牌的优先级：
1. 本机已经存过的令牌（钥匙串或文件）；
2. 本机装了 `gh` 并且已登录，`gh auth token` 能读到两个仓库：直接用，什么都不用输；
3. 包里有 `sealed-tokens.json`：控制窗口只显示一个"解锁密码"输入框，加一个"改用令牌"的小链接。
   - 输对了就解密并存进本机，以后不再问。
   - 输错就提示"密码不对"，可以重试。
   - 连续输错 5 次，等 30 秒再试。
4. 都没有：回到现在的两个令牌输入框。

**4. 设置页**：保留"更新令牌"的入口，令牌过期或者想换的时候用。

**5. 依赖**：`cryptography` 加进启动器运行时的依赖和锁文件。三个系统的 Python 3.14 都有现成的 wheel，用 abi3 那种，构建要能通过。

**6. 测试**：
- 加密再解密能还原；
- 密码错误；
- 密文被篡改（GCM 校验失败）；
- 版本或仓库名对不上；
- 启动器四种来源的优先级；用 mock 来测，不要调用真实的 GitHub 和 gh。
- 脚本的 `.env` 解析：注释、引号、空行、等号两边有空格。
- 脚本**不打印**令牌：捕获输出来断言。

**7. 文档**：
- `deploy/README.md`「在一台新电脑上用」改成：下载 → 打开 → 输解锁密码 → 完成。手动粘贴令牌的方式保留，作为备用。
- 加一节"发新安装包和换令牌"：
  1. 改 `.env`；
  2. `uv run scripts/desktop/seal_tokens.py`；
  3. 打新标签。
- 写清楚：明文令牌只在用户本机的 `.env` 里，仓库和安装包里只有加密后的内容；密码别和别的账号共用。
