## 要做的事

### 1. 题（`problems/sql/1/`、`problems/sql/2/`）

- **编号**：题号 `sql-1-NNN-slug`、`sql-2-NNN-slug`，NNN 从 001 起。order 从 10 起、步长 10。
- **格式**：照 `docs/problem-format.md` 的 SQL 部分，比着阶段 0 的题写：`problem.yaml`、`statement.md`、`solution.sql`、`datasets/`，补全题和改错题还有 `starter.sql`。
- **数据**：
  - 阶梯题优先用书店库。
  - SQL 50 的题可以用书店库改编；也可以自带小表，放在题目自己的 datasets 里，写 schema + 数据。
  - **要在书店库加数据或加表时**，只追加行或新表，不改已有的行：06 号任务和后面的 SQL 任务也会用这个库。加了什么写进报告。
- **数据集**：每题一个可见样例数据集 + 至少 2 个隐藏数据集，覆盖：
  - NULL 参与聚合（COUNT(*) 和 COUNT(列) 的差别）
  - 空分组
  - 并列
  - LEFT JOIN 后右表为空
  - 一对多连接导致重复计数
- **`wrong_examples`**：每题至少 1 条典型错误写法，并确认它在至少一个隐藏数据集上和参考解结果不同（verify_sql 会查）。常见的错误：
  - HAVING 写成 WHERE
  - COUNT(*) 和 COUNT(列) 搞混
  - INNER 写成 LEFT
  - 连接后重复计数
  - 漏了 GROUP BY 列
- **SQL 50 的题**：写 `leetcode: <slug>`，题面自己写，测试数据自己造。
- **技能标注**：`requires` / `introduces` 规则同 Python，最多引入 1 个新技能。`check_curve.py` 用正则扫描参考解。识别表缺规则时，在 `SQL_RULES` 里加行，只加不改。

### 2. 技能卡和课

- `problems/sql/skills.yaml`：阶段 1–2 的技能卡扩写成完整知识卡，比照阶段 0 的卡。只改阶段 1–2 的条目。
- 课文件：`problems/sql/lessons/sql-1-lNN-…`、`sql-2-lNN-…`，每阶段 1–3 个文件。
  - 每个技能都要有：讲解（read）、可运行示例（example：写清楚用哪个 db，可以带 patch 加几行数据来演示边界）、针对误解的小测（quiz）。
  - 示例要能在 verify_sql 里跑通。
  - 连接的讲解要有"行数会怎么变"的直觉：一对多、多对多、LEFT JOIN 补 NULL。

### 3. 文档

- `docs/curriculum.md` 第 7 节阶段 1、2：标"已写"、写实际题数；顺序有调整就同步。
- `docs/teaching-design.md`：SQL 误解目录里补阶段 1–2 的误解，编号接着现有的往下编。

## 验收标准

1. `python3 scripts/curriculum/verify_sql.py --only sql-1` 和 `--only sql-2` 全过，阶段 0 也照旧全过（`--only sql-0`）。
2. `server/.venv/bin/python scripts/curriculum/check_curve.py --track sql`：阶段 1–2 范围内 0 错 0 警。计划覆盖（SQL 50）照旧满足。
3. 题目能被平台加载：`/api/tracks/sql/problems` 里能看到新题，`load_errors` 为 0。
4. 报告里列出：两个阶段各自的 SQL 50 题数和阶梯题数、题型统计、对书店库的改动。
