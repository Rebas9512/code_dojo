# 40-flow-session：一组练习、专注模式、安静计时、通过提示音

## 背景

用户 2026-11-23："做题的时候毕竟还是做题 感觉目前有点难进入心流状态，能不能帮我调查一下有没有什么好的小机制或者小设计能帮着我做题进入心流状态的"。

主控的调研报告在 `docs/reports/做题心流 调研.md`，先读第 1、3 节。结论是：题目层面的设计不错，缺的是一次练习的节奏。用户看完后选了这一轮要做的：**一组练习（带热身和连续首次通过计数）、专注模式、安静计时、通过提示音（默认关）**。

相关代码：
- 做题页 `web/src/components/ProblemWorkspace.tsx`：`ActiveProblem`、`useElapsed`、`judge`、`onResult`，状态栏 `.wb-status`，命令面板 `commands`。
- 布局 `web/src/components/WorkbenchLayout.tsx`、`workbench.css`。
- 主页 `web/src/pages/MapPage.tsx`：顶栏已有"继续"按钮，规则在 `mapTree.ts` 的 `resumeTrack` 和后端 `tracks()` 的 `frontier`。
- 今日计划和复习：`api.today`，以及 `web/src/pages/PlanPages.tsx`、`practicePath()` 带 review 参数的打开方式。
- 后端：`server/app/units.py` 的 `progress_frontier()`，`main.py` 的 `/api/tracks`、`/api/today`。

## 要做的事

### 1. 一组练习

- **入口**：主页顶栏"继续"按钮旁加"开始一组"。今日计划页也可以放一个，可选。
  - 组的大小可选 3 / 5 / 8，默认 5，记在偏好里。
  - 整组时间盒可选：不限时 / 25 分钟 / 45 分钟，默认不限时，记在偏好里。
  - 这两个选项做成按钮旁边的一个小下拉或弹层，不要另开设置页。
- **排题**：后端新增一个接口（建议 `GET /api/session-plan?tab=python|sql&size=5`），选题逻辑写成纯函数放在 `units.py` 或新文件里，方便单测。
  1. **热身**：当前标签页可见的学习线里，到期的复习题最多 2 道，逾期最久的在前，用现有今日计划的数据。
  2. **新题**：取当前标签页最近练过的线（和"继续"按钮选线的规则一致，没练过就取根线），从这条线的 `frontier` 开始，按地图顺序往后取没做过的非 optional 题，补满 size。不够就少几题，不跨线。
  3. 每一项返回能直接打开的链接信息：复习项要带 review 来源和到期日，和今日计划打开复习的方式一致。
- **组的状态**：放在前端 localStorage，不进后端数据库。存 id、题目列表、当前第几题、开始时间、时间盒、每题结果（首次提交是否通过、是否跳过、用了几次提示 / AI）。刷新页面或重开应用后能接着做；开始超过 12 小时的组视为作废。组进行中时，主页的"开始一组"变成"继续这组 2/5"。
- **做题页顶部的组条**：放在编辑区上方，或者和现有标签条合并，自己判断，要安静、一行高。内容依次是：
  - 进度点 `●●○○○ 2/5`；
  - "连续首次通过 N"；
  - 时间盒的细进度条（选了时间盒才显示）；
  - "跳过"和"结束这组"两个文字按钮。

  组条只在当前题属于这组时显示。用户从组里点去别的题，组条就不显示；回到组里的题再出现。
- **推进**：
  - 当前题提交**通过**后，组条显示"通过 ✓ · 1.5 秒后进入下一题（Esc 留下）"，1.5 秒后自动打开下一项。按 Esc 取消自动跳转，组条换成"下一题 →"按钮。
  - 提交没通过就留在这题，可以重试，也可以点"跳过"。
  - "首次通过"按这道题在这组里的第一次正式提交算，运行样例不算。
  - 时间盒到点时组条显示一行"时间到，做完这题就收"，不打断、不跳转。做完当前题后，下一步直接进小结。
- **小结**：最后一题完成或点"结束这组"后进入小结。可以是一个路由，比如 `/session`，也可以是主页上的一层。内容：
  - 题数、首次通过数、跳过数、用到提示或 AI 的题数、总用时、最高连续首次通过数；
  - 逐题列出状态，可以点回去；
  - 两个按钮："再来一组"（按当前进度重新排）、"回地图"。
  - 风格安静、字少，遵守 `.impeccable.md`。

### 2. 专注模式

- **开关**：一个快捷键（建议 `Alt+Z`，先确认和现有快捷键不冲突，冲突就另选，写进报告），命令面板加一条，状态栏也放一个小开关。状态记在偏好里，跨题保持。
- **开启时**：收起本单元题目列表（Explorer）、助教栏、面包屑和应用顶栏（快速打开、今日计划等），状态栏只留最少的几项（语言、裸写、退出专注）。
  - 助教仍然可以用 Ctrl+Alt+I 临时打开。
  - 同步状态的提示在专注模式里不弹，只记着，退出后再显示。
- **全屏**：开启时调用 `document.documentElement.requestFullscreen()`，Electron 的渲染进程支持，不用改 `desktop/`；关闭时退出全屏。用户按 Esc 退出全屏时，专注模式保持开着，只是不全屏。
- **和组的关系**：开始一组时自动打开专注模式；组结束不自动关，由用户决定。

### 3. 安静计时

- 状态栏的"本题用时"不再每秒刷新：去掉 `useElapsed` 每秒的 `setInterval` 重绘。
  - 用时改为提交时用开始时间算（交给后端的 `elapsed_ms` 不变）。
  - 状态栏只留一个时钟图标，悬停时 `title` 显示"本题用时 N 分钟"，悬停那一刻再计算。
- 组的时间盒见第 1 节，只用细条表示，不显示跳动的数字。
- 这样做题页不会每秒重渲染一次，报告里写一下前后的重渲染情况。可以用 React Profiler 或简单计数，测个大概。

### 4. 通过提示音（默认关）

- 偏好 `dojo-sound`，默认关。开关放在命令面板（"开关通过提示音"），以及专注模式和组条附近的一个小图标，自己挑一个地方。
- 打开时，正式提交通过就播一个很轻、很短（150 ms 以内）的提示音。用 WebAudio 现场合成，比如两个柔和的正弦音，不加音频文件。没通过不出声。

## 不做

- 不做组内自适应、事先定规则、"停下留一句"（这轮用户没选）。
- 不改掌握度和复习的判定规则，组只是换个方式把题串起来。
- 不改 `desktop/`、`bootstrap/`（那些要发新的安装包）。
- 不加新依赖。

## 验收标准

- `cd server && .venv/bin/python -m pytest -q` 全过（7 个会建临时 git 仓库的同步测试可以按标准做法排除）。新增测试覆盖排题纯函数：
  - 有复习时最多取 2 道放在前面；
  - 新题从 frontier 往后取、跳过做过的和 optional 的；
  - size 不够时少给、不跨线；
  - 空记录时从根线开始。
- `cd web && npm run build` 通过。
- 起测试实例（后端 8001、前端 5174，`CODE_DOJO_AI_PROVIDER=off`，`CODE_DOJO_JUDGE=local`，独立数据目录）。用 Playwright 走一遍，截图放 `{RUN_DIR}/`：
  1. 空数据：主页点"开始一组"（size 3），进第 1 题，组条显示 `1/3`，专注模式已开（题目列表和助教收起）。
  2. 用参考解（题目目录下的 `solution.py`）提交，通过后约 1.5 秒自动进第 2 题，"连续首次通过 1"。
  3. 第 2 题先交一个错的，再点"跳过"，进第 3 题，连续计数归零。
  4. 第 3 题通过后进入小结，数字正确（首次通过 2、跳过 1）。
  5. 组进行到一半时刷新页面，组条和进度还在；回主页显示"继续这组"。
  6. 专注模式开关后，被收起的元素都回来；Esc 取消自动跳转生效。
  7. 状态栏不再每秒变化：记两次状态栏文本，间隔 2 秒，应该相同。
  8. 打开提示音后通过一题，确认创建了 AudioContext 并播放了（可以 stub 或监听）；关闭时不创建。
- `docs/README.md` 写做题页功能的地方补"一组练习 / 专注模式 / 计时 / 提示音"的说明，写成"现在是什么样"，只用小补丁改。
