# 25 · 平台：一条命令启动（Linux / macOS / Windows），做题记录跨机器同步

## 背景

用户 2026-11-22 说：
- "能不能把这个项目做成调用机器本地python之类的 然后github存题库每次同步题库就行"
- "做成3系统支持吧，那这样还能做成一个网页的形式吗"

主控定的方案：
- 每台机器本地跑，形式还是网页（localhost 加浏览器）。
- 代码和题库在一个 GitHub 私有仓库，`git pull` 同步。
- 做题记录用"只追加的事件日志 + 单独的私有 git 仓库"同步：每台机器只写自己的文件，读的时候合并，不会冲突。

本地判题（不靠 Docker）是 24 号任务，两个任务同时跑。

**并行**：先读 `codex/PLAN.md`。
- 24 号任务会改 `judge/`、`server/app/judge.py`、AI provider 的跨平台部分，还有 `config.py` 里判题的配置项。
- 你在 `config.py` 里只加启动和同步相关的配置项，用小补丁改。
- 16、19 两个内容任务也在跑。

你名下的东西：
- 启动器
- `server/app/db.py` 的导出和导入
- 新建的同步模块
- 前端里和同步状态有关的那一小块
- `docs/README.md`「怎么跑」和部署两节
- `deploy/README.md` 里补一节"本地模式"

## 要做的事

### 1. 启动器 `dojo`

一个跨平台的入口：
- 根目录放 `dojo.py`，用 `uv run dojo.py` 启动；
- 再配两个薄壳：`dojo`（sh，给 Linux 和 macOS）和 `dojo.ps1`（给 Windows），双击或者一条命令就能跑。

依次做这些事，每一步打印一行中文进度：

1. **检查依赖**：git、uv、Node。缺了就给出中文安装指引，每个系统一条命令，然后退出。Claude Code 是可选的，没有的话提示"AI 助教会关闭"。
2. **同步题库**：工作区干净时 `git pull --ff-only`；有本地改动就跳过并提示。加 `--no-pull` 参数可以跳过这一步。
3. **准备后端**：`uv sync`（server）。
4. **准备前端**：
   - `web/node_modules` 不存在或 lock 文件变了就 `npm ci`；
   - 源码比 `web/dist` 新就 `npm run build`；
   - `scripts/curriculum` 下的 Node 依赖同理，SQL 期望结果要用。
5. **同步进度**：先拉一次（见第 2 节）。
6. **起服务**：单进程单端口，用 13 号任务做的生产托管，FastAPI 直接托管 `web/dist`。
   - 默认 `127.0.0.1:8765`，**只听本机**，`CODE_DOJO_AUTH=off`，因为只有本机能访问。
   - 端口被占用就换一个。
   - 数据目录默认放在系统的用户数据目录：Linux 是 `~/.local/share/code-dojo`，macOS 是 `~/Library/Application Support/code-dojo`，Windows 是 `%APPDATA%\code-dojo`。
   - 可以用 `CODE_DOJO_DATA` 覆盖。
7. **打开浏览器**：`webbrowser.open`。
8. **退出**：Ctrl+C 时推送进度，然后退出。另外**每 10 分钟**、以及每次提交通过后也推送一次，失败只记日志、不打断做题。

另外加一个子命令：`dojo doctor`，检查环境和依赖并打印状态。

### 2. 做题记录同步

- **同步什么**：
  - 提交记录（含代码、结果、AI 协助标记、用时、提示数）
  - 复习日程和复习结果
  - 设置（比如每日复习上限）
  - 助教对话
  - 附加题（AI 出的题，规格要完整，换台机器也能做）

  先看 `server/app/db.py` 的表结构，决定事件类型。

- **事件格式**：
  - 每条事件带全局唯一 id（uuid）、机器 id、时间戳、类型、内容。
  - 存成 JSONL，按机器和月份分文件：`<机器 id>/2026-11.jsonl`。
  - 机器 id 第一次运行时生成，存在数据目录里。
- **本地库和事件日志的关系**：本地 SQLite 照旧是运行时用的库。
  - 写入时同时追加事件。
  - 启动拉取后，把别的机器的新事件导入本地库：按 uuid 去重，导入要幂等。
  - 复习日程、掌握度这类派生数据由事件重新推出来，或者按时间戳以最后写的为准，你选，写进报告。
- **同步仓库**：
  - 地址配置在 `CODE_DOJO_SYNC_REPO`，是一个**单独的**私有 git 仓库，不放进代码仓库，克隆到数据目录下的 `sync/`。
  - 拉取：`git pull --rebase`。推送：`git add 自己的目录 && commit && push`。
  - 因为每台机器只改自己的目录，rebase 不会冲突；万一冲突了，就保留双方的行，JSONL 本来就是只追加的。
  - 没配置同步仓库就只在本机记录，界面上显示"未开启同步"。
- **迁移**：现有的 `server/data/` 里已经有做题记录。提供 `dojo import-legacy <旧数据目录>`，把旧库一次性转成事件，不要直接读写用户的真实库来测试，自己造一个旧库来测。
- **界面**：页面右上角显示一个小的同步状态：上次同步时间、未推送条数、失败原因。点一下立即同步。字少。

### 3. 文档

- **`docs/README.md`**：
  - 「怎么跑」第一条改成"本地模式：装 git、uv、Node，`git clone` 后运行 `./dojo`（Windows 运行 `dojo.ps1`）"；开发模式（Vite 加 reload）保留在后面。
  - 部署一节改成：本地模式是默认，服务器部署（13 号任务做的）是可选项。
- **`deploy/README.md`**：补一节"本地模式和同步仓库怎么建"：
  - 在 GitHub 建一个私有仓库；
  - 配 SSH key 或者 `gh auth`；
  - 把仓库地址填进配置。
  - 文档里不要写用户的账号名，用占位符。

### 4. 测试

- **同步**：用两个临时数据目录模拟两台机器，加一个本地 bare 仓库当远端：
  - A 机做题、推送；
  - B 机拉取后看到 A 的记录和复习日程；
  - 两边同时做题后都能合并；
  - 重复导入不会出现重复记录。
- **启动器**：依赖检查、端口占用时换端口、`--no-pull`、数据目录选择。用 mock 来测，不要真的去 clone 或者打开浏览器。
- **`import-legacy`**：用造出来的旧库测。

## 验收标准

1. `server/.venv/bin/python -m pytest -q` 全过，包括新的同步和启动器测试。
2. 在本机（Linux）实际跑：
   - `./dojo --no-pull`，数据目录和端口用测试专用的，不要用 8765 以外被用户占用的端口；
   - 浏览器能打开、能做题，`dojo doctor` 输出正常；
   - 用一个本地 bare 仓库当同步仓库，两个数据目录之间同步成功。
   - 截图放 `{RUN_DIR}/`。
3. Windows 和 macOS 用不了的东西（比如 sh 脚本），在 `dojo.py` 里按平台分支处理，并在报告里列出"只在 Linux 上实测、其他系统靠 24 号任务的 CI"的部分。
4. 用户的 8000 和 5173 实例没被动过，`server/data/` 没被改过，也没读过。
