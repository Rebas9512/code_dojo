# App 增长看板的数据

完整运行与导出的 `dashboard.sql` 使用本线的 `readerapp`。在空库中依次执行建表、种子数据、看板脚本，即可得到 2025-03-15 的快照；前两步也可以直接使用项目页的「下载数据」。[建表 SQL](../../../_db/readerapp/schema.sql) · [种子 SQL](../../../_db/readerapp/seed.sql)

全库有 48 位读者、276 次登录、855 条操作、47 条实验分组和 126 笔交易。本项目约定原始时间戳为 UTC，注册日期已经是本地日期。业务时钟为固定 UTC+08，观察截止点为本地 2025-03-16 零点，截止点本身不计入。登录定义活跃，操作定义会话和购买路径，正金额交易用于确认实验付费。

## 单题数据

所有部分共用以下数据。运行样例取五位读者；每份题面还列出完整库的示例。正式提交会在五个独立的数据集上检查本题，前面部分的视图由参考答案建立。

| 数据集 | 核对的情形 |
|---|---|
| `example.sql` | 用五人小样本替换种子，含重复上报、跨午夜访问、同秒漏斗动作和七天整付款。 |
| 原始种子 | 八个部分使用相同的业务快照，可逐项对照最终看板。 |
| `boundaries.sql` | 在原始库追加滚到周一的登录、相差一秒的会话与实验窗口、恰好到观察截止点的记录。 |
| `quiet.sql` | 最近才注册、没有活动的读者，没有成熟的批次或实验组。 |
| `history.sql` | 用跨年历史替换种子，含空月、回流、同秒下单、同组重报和跨组者。 |
